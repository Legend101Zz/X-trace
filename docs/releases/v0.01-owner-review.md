## 11. Known gaps in this candidate (honest list)

Product, from the lane reports and the Petclinic campaign (run `37929608737`, an earlier head):
1. Recordings per request: only 12 of 65 requests (about 13 to 14 recordings for about 50) were recorded in the Petclinic campaign. Capture is lost or sampled without a written rule.
2. Redirects (302) are recorded as `http.response 200`; the status is read before the redirect is committed.
3. Outcome: `unobserved` is common and `httpStatus` is often null. The 500 paths (`/owners/999999`, `/oups`) show an unavailable response or no recording. Outcome persistence was added late with tests; the Java side that feeds it is not complete.
4. No Spring Data repository frames; only controller and domain frames appear.
5. Source file and line are mostly absent (`source: null`). Java line probes exist (61/61 on the verification corpus on JDK 17 and 21) but are not wired for normal use; focused mode is claimed, not granted, by the agent.
6. Audit redactor: the blocker (the redactor was never invoked) was fixed late on the candidate (loopback canary test, stack-frame scrub), then merged at the last step. The final independent review of this exact head was still running; treat the privacy claim as unproven until it reports. The privacy canary scan over the Petclinic campaign output was clean on an earlier head.
7. Capture budget: the event cap was raised 8x without the full resource budget (digest memory, finish bound). Large recordings can finish Partial with the reason `verification_budget_exceeded`. Expect no hard guarantee on memory for very large recordings.
8. Navigation (over/out/aroundFrame) fixes landed late; async-root descendants and other threads are ranked by depth only (documented residual).
9. Node: Express 4 and 5 route templates are captured, but a custom body-reading middleware can lose request context so the handler frame is missing while the recording reads complete; route, status and outcome are not persisted to the read API.
10. Catalog: migration v9 is not registered; the store-level refusal of static-snapshot claims was removed in the last fixer round and enforcement now sits only at the application port (flagged for scrutiny); incomplete-scan reasons are not stored; the observed side of reconciliation exists only for the Spring `POST /orders` fixture.
11. `exercise`, `export`, `retention`, `store` (backup/verify/restore) and `doctor --bundle` are stubs (exit 9).
12. TUI: bounded to 500 events and 50 recordings; CLI wiring untested.
